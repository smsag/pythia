Design brief · v2 · replaces v1 of the same day

Pythia conversation controls

Make the instructions behind every answer readable and changeable from the header: which model answers, how much it reasons, and which language it has been told to write in.

Pythia for Obsidian 2.18.0 · 16 Sep 2026

Discard these parts of the v1 designs

  • The status strip / rail with template, web, vault, notes and note writing (1a–1c). Template, web search and vault context already have controls in the toolbar next to Senden; repeating them in the header is noise.
  • The settings panel redesign (1e). The conversation settings dialog is not part of this brief and stays as it is.
  • The state grammar sheet (1d) as a general system for every chip. What's needed is narrower: for each value below, show whether it's the default or set for this conversation.
The one job

Looking at the header, a user can say: “this conversation is answered by Sonnet 5, reasoning High, instructed to write in German.” And they can change any of the three with a tap on it.

Today only the model is visible. Reasoning and language sit in a dialog reached through the model popover's footer (two taps), so users don't know they exist. The language case is the sharpest: German, the Obsidian language, and “the conversation's language” produce very different instructions to the model, and nothing on screen tells them apart.

Scope

The values to surface

Three are always visible. Two appear only when this conversation has its own value. UI labels are German first; the plugin also ships English.

Model

Always

Already in the header. Keep it, and keep its picker (provider groups, speed · depth · cost, context window). It's the anchor the other values attach to.

Reasoning (“Effort” in code and settings today)

Always

How much the model thinks before answering. Higher means more thorough, slower and more expensive, and the thinking counts against the token limit.

Language

Always

The language the model is instructed to write in. It applies to the answer and to everything generated for the conversation: title, summary, glossary definitions.

Changing it doesn't translate answers already written. Say so at the moment of change, not in the header.

Temperature

Only when set for this conversation

0–1. Low is factual and repeatable; high is varied. Global default is 0.7. Reasoning models ignore it; if one is pinned on such a model, show it as not applied.

Token limit

Only when set for this conversation

Maximum length of one answer. The “too low for this reasoning model” warning already appears beside Senden, so don't repeat it in the header.

Rules

How the values behave

  • Show what's sent, never just “Standard”. A default value is displayed resolved (“Hoch”, “Deutsch”) with a quiet marker that it's the default, never the bare word “Standard”.
  • Default and “set for this conversation” look different, and both are changeable. Every picker offers a way back to the default. Picking the default must not store today's default value, so the conversation keeps following the global setting when it changes.
  • Change in place. Tapping a value opens a small picker for that value alone, anchored to it (a bottom sheet on mobile is fine). One tap to open, one to choose, applied immediately, no Save button, no detour through the settings dialog.
  • Understandable without hover. Most use is on iPhone. Anything a tooltip would explain must be visible in the picker itself: one short line under each option is enough.
  • Fits a 300 px sidebar. Show how it degrades at 300, 380 and 450 px. If space runs out, rename / copy link / delete may move into an overflow menu. The conversation name may truncate; the model, reasoning and language may not disappear.
Deliver

Frames wanted

  • Header at 300 / 380 / 450 px and iPhone width, light and dark
  • States: everything default · language pinned · “Sprache des Gesprächsverlaufs” (no instruction) · Obsidian language resolved · reasoning on a model without effort · temperature pinned · temperature pinned on a reasoning model
  • The open picker for language and for reasoning, desktop and mobile
Do not draw

Out of scope

  • The conversation settings dialog
  • Template, attached notes, web search, vault context (their controls are at Senden)
  • Note-writing permission, history/resume mode, glossary theme, output folder (tracked separately)
  • Context usage (keep the existing line)
  • Anything below the header
Constraints

Native to Obsidian

  • Only Obsidian CSS variables (--color-accent, --text-faint, --background-modifier-border…). No custom background colours, no hardcoded accent, no shadows except on popovers.
  • 4 px spacing grid. 11 / 12 px type. --font-monospace for values and labels, --font-interface for the name. No imported fonts, no emoji.
  • Icons are Lucide (Obsidian's set), 12–14 px, stroke 1.6. Text on an accent fill is pure black or white.
  • No hover-only states; :hover styles only for pointer devices. No animated transitions on fills that show state.
  • The panel fills its leaf flush: no radius, no outer padding.
